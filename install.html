Install Garrison 0.2.0

Docker Compose is the quickest way to see it work. Kubernetes adds per-run pod isolation and cluster deployment. The commands on this page are copied from the repository's documentation.

Garrison 0.2.0 images are jchristn77/garrison-server:v0.2.0, jchristn77/garrison-worker:v0.2.0, and jchristn77/garrison-dashboard:v0.2.0. Compose, the Kustomize base, and the Helm chart in the 0.2.0 source pin that tag; the local scripts below build the images from your checkout. Never deploy latest.

Docker Compose

Docker Compose

Compose runs a control plane, two workers, PostgreSQL, the dashboard, a one-shot bootstrap, and Prometheus, Grafana, Tempo, Loki, and Alloy.

$ git clone https://github.com/jchristn/Garrison && cd Garrison/docker
$ ./update.sh  # generates keys into .env, builds the images, starts the stack; Windows: update.bat

update.sh writes any missing keys and passwords into docker/.env, checks that the host ports are free, builds the three images tagged v0.2.0, and starts the stack. It prints the administrator password once; afterwards it is GARRISON_ADMIN_PASSWORD in docker/.env. ./update.sh --pull pulls the published images named in compose.yaml instead of building.

Optional harness credentials (Claude, Codex, Mux) go in docker/.env too. Every port binds to 127.0.0.1 only.

k3s and minikube

k3s and minikube

The scripts build the images, generate secrets, apply the overlay, and wait for every rollout and the bootstrap Job. The local overlays run one server, two workers, the dashboard, PostgreSQL, and a bootstrap Job in namespace garrison.

K3S in Docker with k3d (macOS and Windows)

$ git clone https://github.com/jchristn/Garrison && cd Garrison
$ brew install k3d  # or see https://k3d.io for other platforms
$ k3d cluster create garrison --api-port 127.0.0.1:6550 -p "127.0.0.1:8080:80@loadbalancer"
$ K3D_CLUSTER=garrison k8s/scripts/deploy-k3s.sh --build

K3S on a Linux host

$ k8s/scripts/deploy-k3s.sh --build

minikube

$ export ANTHROPIC_API_KEY=...  # optional, any of the harness variables
$ k8s/scripts/deploy-minikube.sh

minikube with images you already built

$ minikube start --driver=docker --cpus=4 --memory=3g
$ for i in server worker dashboard; do minikube image load jchristn77/garrison-$i:v0.2.0; done
$ SKIP_BUILD=1 k8s/scripts/deploy-minikube.sh

Check it and reach it

$ k8s/scripts/smoke-test.sh  # invokes a test-harness agent and checks it succeeds
$ k8s/scripts/port-forward.sh  # REST, MCP, and dashboard on 127.0.0.1:8700, 8701, and 8080

Read the generated administrator password

$ kubectl -n garrison get secret garrison-secrets -o jsonpath='{.data.admin-password}' | base64 --decode; echo
On macOS and Windows, with minikube's Docker driver, the minikube ip address is not reachable from the host; use k8s/scripts/port-forward.sh. Start with MINIKUBE_MEMORY=6g if Docker Desktop only has 8 GB.

Kubernetes guide

Kubernetes

Production Kubernetes

The production overlay expects a managed PostgreSQL and a TLS certificate. It runs three control-plane replicas spread across zones and nodes, an HPA from 2 to 10 replicas, disruption budgets, four workers with 50 GiB workspaces, and an ingress-nginx Ingress with TLS.

  1. Database

    Create Secret garrison-db with keys host, port, database, username, and password.

  2. TLS

    Create Secret garrison-tls for your host name, for example with cert-manager.

  3. Host name

    Replace garrison.example.com in overlays/production/ingress.yaml, and set GARRISON_EXTERNAL_BASE_URL so A2A agent cards advertise it.

  4. Images

    Pin the v0.2.0 tags with kustomize edit set image or an images: block in your own overlay.

  5. Apply

    Generate secrets and apply the overlay.

$ k8s/scripts/generate-secrets.sh
$ kubectl apply -k k8s/overlays/production

Or the Helm chart

$ k8s/scripts/generate-secrets.sh
$ helm install garrison k8s/helm/garrison -n garrison -f k8s/helm/garrison/values-k3s.yaml --set smokeTest.enabled=true
$ helm test garrison -n garrison

The chart renders the same resources as the Kustomize base and expects the same Secrets. It ships values-minikube.yaml, values-k3s.yaml, and values-production.yaml to match the overlays, plus values-worker-pools.yaml for a second worker pool. The most useful values are image.tag, database.mode, server.hpa, ingress, and workerPools.

MCP clients connect at https://<your host>/mcp. More than one control-plane replica needs PostgreSQL; the server refuses to start on SQLite when more are expected.

From source

From source

You need the .NET 10 SDK, and Node.js 22 for the dashboard and app UI. Run each process in its own terminal from the repository root.

$ dotnet build src/Garrison.sln
$ cd src/Garrison.Server && GARRISON_ALLOW_INSECURE_DEFAULTS=true dotnet run -f net10.0  # development mode; Sqlite; REST and A2A on 127.0.0.1:8700, MCP on 8701
$ cd src/Garrison.Worker && dotnet run -f net10.0  # one worker; a second needs its own GARRISON_WORKER_NODE_NAME and GARRISON_WORKER_HEALTH_PORT
$ cd dashboard && npm install && npm run dev  # dashboard; open the URL it prints
$ cd app-ui && npm install && npm run dev  # app UI on http://127.0.0.1:3100/apps/{slug}/

A worker runs only the harnesses it finds on its PATH. Development guide

First app

Your first app in the studio

This path uses the test harness, so it needs no model credentials. Run it from the repository root against the Compose stack. In the dashboard it is the Studio tab under Agents; here it is the same API with curl.

1. Sign in

API=http://127.0.0.1:8700/v1.0/api/tenants/default
GARRISON_ADMIN_PASSWORD=$(grep -E '^GARRISON_ADMIN_PASSWORD=' docker/.env | cut -d= -f2-)
TOKEN=$(jq -n --arg p "$GARRISON_ADMIN_PASSWORD" '{email:"admin@garrison",password:$p,tenantId:"default"}' |
  curl -s -X POST http://127.0.0.1:8700/v1.0/token -H "Content-Type: application/json" --data-binary @- | jq -r .token)

2. Draft an agent, its dev deployment, and an app

D=$API/studio/drafts
DRAFT=$(curl -s -X POST $D -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"title":"Help desk"}' | jq -r .id)
put() { curl -s -X PUT "$D/$DRAFT/items/$1/$2" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d "$(jq -n --argjson v "$3" --arg doc "$4" '{version:$v,document:$doc}')" | jq -r .version; }
V=$(put Agent desk-entry 1 $'apiVersion: garrison/v1\nkind: Agent\nmetadata:\n  name: desk-entry\n  description: Answers people.\nspec:\n  displayName: Help desk\n')
V=$(put Deployment desk-entry-dev $V $'apiVersion: garrison/v1\nkind: Deployment\nmetadata:\n  name: desk-entry-dev\nspec:\n  agent: desk-entry\n  harnessProfile: builtin/fake\n  environment: dev\n')
V=$(put AgenticApp desk $V $'apiVersion: garrison/v1\nkind: AgenticApp\nmetadata:\n  name: desk\nspec:\n  entry: desk-entry\n  members:\n    - { agent: desk-entry }\n  environments:\n    - { environment: dev, deployment: desk-entry-dev }\n  liveEnvironment: dev\n  authMode: Anonymous\n  anonymousEnabled: true\n')
curl -s $D/$DRAFT/diff -H "Authorization: Bearer $TOKEN" | jq -c '.items[] | {kind, name, change}'

3. Request apply and approve it

APPROVAL=$(curl -s -X POST $D/$DRAFT/request-apply -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d "{\"version\":$V}" | jq -r .id)
curl -s -X POST $API/approvals/$APPROVAL/decide -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"decision":"Allow"}' | jq -r .status

4. Talk to it

Open http://127.0.0.1:8080/apps/desk/ and send a message; the test harness echoes it back. Next, try a change in the playground, promote the app to staging and prod, or give the agent architect a deployment and design with it.
